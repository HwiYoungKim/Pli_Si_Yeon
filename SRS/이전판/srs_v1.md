# 플리 시연 — 소프트웨어 요구사항 명세서(SRS)

Nov 7, 2026 · @Kim

## 1. 소개

이 문서는 동아리 전용 모바일 앱(캘린더 + 공지 + 소모임 관리)이 갖춰야 할 요구사항을, 구현 방식과 분리해 검증 가능한 문장으로 정의한다.

### 1.1 목적

- 구현자(Flutter 개발)와 기획자가 같은 기준으로 "무엇을 만들어야 하는가"를 확인하도록 한다.
- 모든 요구사항에 고유 ID를 부여해, 구현과 테스트가 ID 단위로 추적되도록 한다.
- 확정된 것, 가정한 것, 추천한 것을 구분해 남은 결정 사항이 드러나도록 한다.

### 1.2 범위

제품명은 현재까지 "플리 시연"이다. 한 개의 동아리에 속한 회원만 사용하며, 여러 동아리를 지원하지 않는다.

| 구분 | 내용 |
| --- | --- |
| 포함 | 메인화면(오늘 정보), 월 캘린더와 일정 관리, 일정 표시 규칙, 소모임(가입·일정·게시판·공지), 설정, 관리자 탭, 동아리 공지, 알림 |
| 제외 | 공공 공간 대여 예약 자체(카카오톡으로 진행), 반복 일정, 여러 동아리 지원, 회원 인증·로그인 방식(보류) |
| 목표 플랫폼 | 휴대폰용 모바일 앱(Flutter). 태블릿·웹은 이번 범위가 아니다 |

### 1.3 정의·약어

| 용어 | 정의 |
| --- | --- |
| 현시연 임원 | 최상위 권한을 가진 회원. 동아리 일정·공지 등록, 소모임장 지정, 계정 정지, 게시글 삭제를 한다. 모든 소모임에 접근할 수 있다 |
| 소모임장 | 소모임 단위의 중간 권한을 가진 회원. 자기 소모임의 일정·가입 승인·추방·공지·게시판을 관리한다 |
| 일반 회원 | 위 두 권한이 없는 회원 |

| 소모임 일정 | 소모임 회원에게 보이는 일정 |

| SRS | Software Requirements Specification, 소프트웨어 요구사항 명세서 |

### 1.4 참고 자료와 문서 구성

- 참고 자료: 앞서 작성한 [디자인 개요 및 기능명세서(FSD)](https://claude.ai/artifact/GCFNze1C95G6o4yRx9CG9A) 초안. 이 SRS는 그 내용을 요구사항 문장으로 다시 구성한 것이며, 이후 기준 문서는 이 SRS다.
- 구성: 2장은 제품의 배경과 제약, 3장은 외부 인터페이스·기능·데이터·비기능 요구사항, 4장은 미결 사항과 추적표를 다룬다.

### 1.5 요구사항 표기 규칙

- 요구사항은 "…해야 한다" 형태의 한 문장이며, 하나의 문장은 하나의 검증 가능한 사실을 말한다.
- ID는 `영역-번호`로 쓴다. 영역: EXT 외부 인터페이스, MAIN 메인화면, CAL 캘린더·일정, DSP 일정 표시, GRP 소모임, NOT 공지, SET 설정, ADM 관리자, ACC 계정·권한, DAT 데이터, NFR 비기능, PRV 개인정보·동의·권한.
- 우선순위: 필수(없으면 출시 불가), 권장(출시 후 빠르게 필요), 선택(여유가 있을 때).
- 상태: 확정(사용자가 정함), 가정(진행을 위해 임시로 정함, 변경 가능), 추천(빠진 기능에 대해 제안한 기본값, 확인 필요).
- 숫자·위치 값(예: 화면 하단 15%)은 디자인 단계에서 조정될 수 있으며, 문서에 "가정"으로 표시한다.

## 2. 전체 설명

이 앱은 한 동아리의 일정·공지·소모임을 한 곳에서 보게 하는 독립형 모바일 앱이며, 서버와 통신해 회원 간 데이터를 공유한다.

### 2.1 제품 관점

- 독립된 신규 제품이다. 기존 시스템을 대체하거나 이어받지 않는다.
- 공공 공간 대여 예약은 앱 밖(카카오톡)에서 이뤄지므로 앱은 예약을 검증하지 않고 일정으로만 보여 준다.
- 서버는 아직 정해지지 않았다. 앱은 서버 종류에 묶이지 않도록 데이터 접근 계층을 분리한다.

### 2.2 제품 기능 요약

| 기능 | 요약 | 상세 |
| --- | --- | --- |
| 메인화면 | 오늘 날짜·현재 시간·오늘 일정을 시간대별 테마로 보여 준다 | 3.2.1 |
| 캘린더 | 월 단위로 일정을 보고, 일정을 추가·수정·삭제한다 | 3.2.2 |
| 일정 표시 규칙 | 일정 종류·소모임별로 순서와 표시 여부를 정한다 | 3.2.3 |
| 소모임 | 소모임 탐색·가입 신청, 소모임 일정, 게시판, 소모임 공지 | 3.2.4 |
| 공지 | 동아리 공지·소모임 공지를 각 화면 상단에서 보여 준다 | 3.2.5 |
| 설정 | 표시 규칙, 알림, 앱 정보를 설정한다 | 3.2.6 |
| 관리자 | 현시연 임원 전용 기능(소모임장 지정, 계정 정지 등) | 3.2.7 |
| 계정·권한 | 일반 회원·소모임장·현시연 임원의 접근 범위를 구분한다 | 3.2.8 |

### 2.3 사용자 클래스

| 사용자 클래스 | 설명 | 중요도 |
| --- | --- | --- |
| 일반 회원 | 일정 조회, 개인 일정 관리, 소모임 가입 신청과 소모임 일정 등록 | 주 사용자 |
| 소모임장 | 자기 소모임의 가입 승인·추방·일정·공지·게시판 관리 | 중간 권한 |
| 현시연 임원 | 모든 소모임 접근, 동아리 일정·공지, 소모임장 지정, 계정 정지, 게시글 삭제 | 최상위 권한 |

한 사람이 여러 소모임에서 서로 다른 역할을 가질 수 있다. 소모임장 권한은 해당 소모임 안에서만 유효하다.

### 2.4 운영 환경

- 휴대폰용 Flutter 앱. 지원 OS(Android·iOS 중 어느 쪽)는 미정이다.
- 서버와 인터넷으로 통신한다. 시간대는 KST를 기준으로 한다.
- 인터넷에 연결되지 않았을 때의 동작은 3.4 신뢰성에서 다룬다.

### 2.5 설계·구현 제약

- 모든 권한 검사는 서버에서 강제해야 한다. 앱 화면에서 버튼을 숨기는 것만으로는 권한 통제로 보지 않는다.
- 앱은 화면(UI), 로직, 데이터의 3계층으로 나눈다 (가정).
- 한 동아리 회원으로 사용 범위를 한정한다.
- 회원 인증과 로그인 방식은 보류 상태이며, 정해지기 전까지 "로그인된 회원"을 전제로 쓴다.

### 2.6 가정과 의존성

- 서버가 로그인·역할 관리, 데이터 저장, 푸시 알림, 계정 정지, 관리자 작업 기록을 제공한다. 서버 선정이 늦어지면 일정이 밀린다.
- 화면 하단 스와이프 영역은 높이의 약 15%라고 가정한다.
- 시간대 테마 구간은 아침 05–11시, 낮 11–17시, 저녁 17–20시, 밤 20–05시라고 가정한다.
- 소모임 가입은 소모임장 승인이 필요하다고 가정한다. 이 가정은 4.1의 미결 사항에 올려 두었다.

### 3.2 기능 요구사항

기능별로 설명 한 문단과 요구사항 표를 둔다. 표의 우선순위·상태 정의는 1.5를 따른다.

| 순서 | 표시 단계 | 기본 표시 |
| --- | --- | --- |
| 1 | 동아리 일정 | 보임 |
| 2 | 공공 공간 사용 일정 | 보임 |
| 3 | 개인 일정 | 보임 |
| 4 | 가입한 소모임 일정 | 보임 |
| 5 | 가입하지 않은 소모임 일정 | 숨김 |

| ID | 요구사항 | 우선순위 | 상태 |
| --- | --- | --- | --- |

| DSP-04 | 캘린더 화면의 눈 모양 버튼을 누르고 있는 동안만 숨겨진 일정을 임시로 표시해야 한다. | 필수 | 확정 |
| DSP-05 | 설정에서 5단계 각각의 순서와 표시 여부를 바꿀 수 있게 해야 한다. | 필수 | 확정 |
| DSP-06 | 소모임 하나 단위와 "가입한 / 가입하지 않은" 그룹 단위로도 순서와 표시 여부를 정할 수 있게 해야 한다. | 필수 | 확정 |

### 4.2 범위 제외

- 공공 공간 대여 예약의 중복 검증과 카카오톡 연동. 대여는 앱 밖에서 진행한다.
- 반복 일정. 대신 CAL-14의 "다른 날짜로 복사"를 제공한다.
- 여러 동아리 지원.
- 회원 인증·로그인 방식의 설계 (보류).
- 태블릿·웹 화면.
